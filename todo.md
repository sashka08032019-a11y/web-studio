Задача: Удаление заглушек, SEO-оптимизация и подготовка сайта к индексации

1. Роль агента

Ты — Senior Frontend Developer и Technical SEO Specialist.

Твоя задача — провести аудит существующего проекта сайта https://web-developer-s.netlify.app/, устранить заглушки в разделе «Портфолио», улучшить качество контента и техническую SEO-оптимизацию, чтобы поисковые системы могли обнаруживать, сканировать и индексировать сайт.

Работай непосредственно с исходным кодом проекта. Не ограничивайся рекомендациями и отчётом: вноси необходимые изменения в файлы проекта, проверяй результат и исправляй найденные ошибки.

2. Основные правила
   Сначала изучи структуру проекта, используемый фреймворк, маршрутизацию, конфигурацию сборки и существующую SEO-реализацию.
   Сохраняй текущий дизайн, визуальный стиль, адаптивность и работоспособность сайта.
   Не переписывай проект целиком, если достаточно точечных изменений.
   Не создавай вымышленные проекты, отзывы, компании, достижения, рейтинги, адреса и другие факты.
   Не заменяй реальные данные фиктивными текстами, случайными изображениями или ссылками-заглушками.
   Не удаляй полезный контент и работающие функции без необходимости.
   Не считай задачу выполненной, пока не проверены сборка, ссылки, SEO-метаданные и доступность сайта для поисковых роботов.
   Если для заполнения портфолио не хватает информации, выяви недостающие данные и подготовь список того, что необходимо предоставить владельцу сайта. Не придумывай содержимое самостоятельно.
3. Аудит и очистка раздела «Портфолио»

Найди все компоненты, файлы, данные и маршруты, связанные с разделом «Портфолио», включая карточки проектов, изображения, описания, кнопки и внешние ссылки.

Найди и устрани следующие проблемы
Карточки без реального содержимого.
Демонстрационные и тестовые проекты, не предназначенные для публикации.
Шаблонные названия и описания.
Тексты Lorem ipsum, Project Name, Your project, Coming soon и аналогичные заглушки.
Изображения-заполнители и повторяющиеся изображения, не относящиеся к проектам.
Ссылки #, пустые href, фиктивные URL и неработающие кнопки.
Кнопки «Демо», «Подробнее», «GitHub» и аналогичные элементы без корректного действия.
Неиспользуемые компоненты, тестовые данные и мёртвый код, связанные с заглушками.
Правила обработки проектов
Сохрани все проекты, для которых имеются реальные данные.
Проверь, что название, описание, изображение, технологии и ссылки каждого проекта соответствуют друг другу.
Если проект существует, но часть информации отсутствует, используй только подтверждённые данные.
Если карточка полностью фиктивная, удали её из публичного портфолио.
Если ссылка на демонстрацию или репозиторий отсутствует, не создавай фиктивную ссылку. Скрывай соответствующую кнопку либо корректно обозначай недоступность действия.
Не скрывай существующие реальные проекты только потому, что у них отсутствует ссылка на GitHub.
Если удаляемый проект доступен по отдельному URL, проверь последствия для SEO. Не оставляй внутренние ссылки на удалённые страницы. Для страниц с подходящей заменой настрой корректный постоянный редирект; для удалённых страниц без замены выбери подходящий HTTP-статус, а не перенаправление всех URL на главную.
Не удаляй полезные страницы и контент, которые могут получать поисковый трафик.
Улучшение оставшихся карточек

Для каждого реального проекта, если данные доступны, обеспечь:

Понятное название проекта.
Уникальное и содержательное описание.
Перечень использованных технологий.
Качественное изображение или скриншот проекта.
Осмысленный альтернативный текст изображения.
Работающую ссылку на проект, если она существует.
Работающую ссылку на исходный код, если он публичен.
Корректную HTML-семантику и доступность с клавиатуры.

Не добавляй искусственные рейтинги, статистику, результаты и неподтверждённые показатели эффективности.

4. Полная техническая SEO-оптимизация

Проведи аудит всего сайта, а не только портфолио.

4.1. Title и Meta Description
Настрой уникальный, информативный <title> для каждой индексируемой страницы.
Добавь уникальный meta name="description" для каждой важной страницы.
Избегай дублирующихся заголовков и описаний.
Используй естественные ключевые слова, соответствующие реальным услугам и содержимому сайта.
Не используй бессмысленные перечисления ключевых слов и keyword stuffing.
Проверь, что метатеги действительно попадают в HTML, доступный поисковым роботам.
Не создавай метатеги для несуществующих страниц.

Если география и целевая аудитория не указаны, не придумывай их. Определи тематику по существующему контенту и запроси недостающую информацию при необходимости.

4.2. Заголовки и HTML-семантика
Проверь иерархию h1–h6.
Используй один основной h1 на страницу как рекомендуемую структуру.
Применяй семантические элементы header, nav, main, section, article и footer там, где они уместны.
Убедись, что ссылки используются для навигации, а кнопки — для действий.
Не создавай фиктивные заголовки ради SEO.
Проверь наличие осмысленного текстового контента на ключевых страницах.
4.3. Robots.txt

Проверь наличие файла /robots.txt.

Если его нет, создай корректный файл в публичной директории, используемой проектом.

Требования:

Не блокировать важные страницы сайта.
Не блокировать необходимые CSS, JavaScript и изображения.
Не запрещать сканирование всего сайта через Disallow: /.
Указывать Sitemap только по корректному абсолютному URL, если карта сайта создана и доступна.
Не пытаться использовать robots.txt как средство удаления страниц из индекса.

После сборки проверь, что файл действительно доступен по адресу:

https://web-developer-s.netlify.app/robots.txt

4.4. Sitemap.xml

Создай или исправь XML-карту сайта по адресу:

https://web-developer-s.netlify.app/sitemap.xml

В карту должны попадать только существующие канонические URL, которые предназначены для индексации.

Требования:

Абсолютные URL с HTTPS.
Корректный XML.
Только канонические страницы с ответом 200 OK.
Отсутствие URL с 404, 5xx, фиктивных маршрутов и редиректов.
Отсутствие страниц, закрытых от индексации.
Исключение внутренних технических маршрутов и дублирующих URL.
Автоматическое обновление карты при изменении списка страниц, если архитектура проекта это позволяет.

Не добавляй фиктивные страницы портфолио в Sitemap. Не устанавливай произвольные значения lastmod: указывай их только при наличии достоверной даты изменения содержимого.

Если сайт состоит из одной страницы, карта должна отражать реальную структуру сайта, а не содержать искусственно созданные URL.

4.5. Canonical и индексируемость
Настрой правильный rel="canonical" для каждой индексируемой страницы.
Используй единый основной вариант URL.
Исключи дублирование из-за завершающего слеша, параметров и альтернативных маршрутов там, где это актуально.
Проверь наличие noindex в HTML и заголовках HTTP.
Убедись, что важные страницы не закрыты от индексации случайно.
Проверь HTTP-статусы страниц.
Не удаляй намеренно установленные ограничения доступа без проверки их назначения.

Canonical должен ссылаться на реальный URL страницы, а не автоматически на главную для всех страниц.

4.6. Open Graph и социальные метаданные

Добавь или исправь:

og:title
og:description
og:type
og:url
og:image
twitter:card

Используй реальные изображения и корректные абсолютные URL. Не придумывай несуществующие файлы изображений.

4.7. Структурированные данные Schema.org

Проверь возможность добавления JSON-LD.

Используй только подходящие типы, например:

WebSite — для сайта.
Person — для личного портфолио, если личность и данные подтверждены.
Organization — если сайт действительно представляет организацию.
BreadcrumbList — для страниц с реальной иерархией навигации.
CreativeWork или другой подходящий тип — для реальных проектов, если их данные соответствуют выбранной схеме.

Требования:

Валидный JSON-LD.
Только достоверные сведения.
Отсутствие вымышленных рейтингов, отзывов и коммерческих данных.
Соответствие структурированных данных видимому контенту.
Отсутствие конфликтующих дубликатов Schema.org.

Не добавляй все типы разметки одновременно без проверки их уместности.

4.8. Изображения и производительность
Оптимизируй изображения без заметной потери качества.
Используй современные форматы, если это совместимо с проектом.
Добавь корректные размеры изображений, чтобы уменьшить сдвиги макета.
Используй lazy loading для изображений ниже первого экрана.
Не применяй lazy loading к основному изображению первого экрана, если это ухудшает загрузку LCP.
Настрой width, height, srcset и sizes, где это необходимо.
Проверь размеры JavaScript-бандла.
Устрани ненужные зависимости и дублирующиеся ресурсы, если это безопасно.
Не ухудшай функциональность ради формального повышения баллов Lighthouse.
4.9. Мобильная версия и доступность
Проверь адаптивность основных страниц.
Устрани горизонтальную прокрутку, перекрытия и выход элементов за пределы экрана.
Обеспечь видимый фокус и навигацию с клавиатуры.
Проверь контрастность текста.
Добавь осмысленные alt для информативных изображений.
Обеспечь доступные названия интерактивных элементов.
